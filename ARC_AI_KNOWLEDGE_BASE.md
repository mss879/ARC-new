## 7. Core FAQs & Technical Guidance

### Q: What is the main difference between legacy WordPress and Next.js Headless architectures?
*   **WordPress (Monolithic)**: The frontend user interface and backend database are tightly bound. Every page load triggers server-side queries to compile the page dynamically. This results in dynamic database latency, plugin vulnerability risks (Plugin Rot), and slower Time-To-First-Byte (TTFB) scores.
*   **Next.js (Headless)**: The frontend is fully decoupled. Pages are pre-compiled into static HTML/React during the build phase and distributed globally via CDNs (e.g., Vercel, Netlify). The frontend calls the database/CMS strictly via secure APIs. This makes the site impervious to SQL injections and enables instant, sub-second page loads.

### Q: What are Google's Core Web Vitals targets?
Any professional corporate site must pass Google's three key telemetry checks for organic ranking:
1.  **LCP (Largest Contentful Paint)**: Measures load speed. Must render the main above-the-fold content in **less than 2.5 seconds**.
2.  **INP (Interaction to Next Paint)**: Measures user responsiveness. The page must respond to clicks or taps in **under 200 milliseconds**.
3.  **CLS (Cumulative Layout Shift)**: Measures visual layout stability. Layout shifts due to loading elements must maintain a score **under 0.1**.

### Q: How do we build multilingual sites for Sri Lankan companies?
We build local sites using Next.js native `i18n` internationalization support. This enables fast, clean transitions between English, Sinhala, and Tamil. The framework uses proper Unicode font rendering for local scripts and structures SEO tags (`hreflang`) so search bots direct users to the appropriate script.
